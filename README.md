# film — 썸네일 선택기

로컬 동영상에서 여러 시점의 썸네일을 만들어 보여주고, 고른 시점 한 장을 **원본 해상도 이미지**로 저장하는 로컬 전용 도구입니다.

- 수 GB 영상도 복사·업로드 없이 그 자리에서 읽습니다 (서버와 브라우저가 같은 컴퓨터).
- 썸네일은 시점을 찾기 위한 탐색용이고, 저장하는 것은 미리보기의 원본 프레임입니다.

자세한 동작과 설계는 [SPEC.md](SPEC.md)에 있습니다.

## 준비물

| 항목             | 버전                                            |
| ---------------- | ----------------------------------------------- |
| macOS            | 우선 지원 (핵심 로직은 OS와 무관)               |
| Node.js          | 26                                              |
| pnpm             | 12 (`package.json`의 `packageManager`)          |
| ffmpeg / ffprobe | 9.x, `PATH`에 있어야 함 (`brew install ffmpeg`) |

ffmpeg가 없으면 화면에 안내가 표시됩니다.

## 시작하기

```sh
pnpm install
cp .env.example .env   # 영상 폴더 지정 (없으면 ~/Movies)
pnpm dev               # http://127.0.0.1:3000
```

```dotenv
# .env
FILM_DIR=~/Movies/MV
```

`FILM_DIR` 아래 하위 폴더까지 `.mp4 .webm .mkv .mov` 파일을 찾습니다. 숨김 파일과 심볼릭 링크는 제외합니다. 환경변수로 넘기면 `.env`보다 우선합니다.

## 사용법

1. 목록에서 영상을 누르면(또는 Enter) 오른쪽 창에서 썸네일 생성이 시작됩니다. 만들어지는 대로 하나씩 나타납니다.
2. 썸네일을 고르면 그 시점의 원본 프레임이 미리보기에 뜹니다.
3. 미리보기 이미지를 우클릭 → **[이미지를 다른 이름으로 저장]**. 파일명은 `원본이름_03m12s450.png` 형식으로 정해져 있습니다.

| 기능             | 방법                                                              |
| ---------------- | ----------------------------------------------------------------- |
| 간격 / 방식      | 1·2·5·10·30초마다(균등) 또는 장면 전환 시점(장면)                 |
| 구간 더 보기     | 고른 썸네일의 앞뒤 사이를 12장으로 다시 나눔. [전체 보기]로 복귀  |
| 프레임 미세 이동 | `,` / `.` = ±1프레임, `Shift + ← / →` = ±1초 (버튼도 있음)        |
| 썸네일 이동      | `← / →`                                                           |
| 저장 포맷        | PNG(기본) · JPEG · WebP — 설치된 ffmpeg가 만들 수 있는 것만 표시  |
| 목록 탭          | 전체 / 최근(이 브라우저에서 연 10개) / 썸네일 있음(한 번 연 영상) |

화면 폭이 900px보다 좁으면 연 영상이 화면 전체를 씁니다. 오른쪽 창의 경계는 끌어서 조절할 수 있습니다.

## 동작 방식

```
브라우저                           서버                         디스크
목록·썸네일 격자 ── ① 열기 ──────▶ 시점 목록 → ffmpeg ×N ────▶ ~/.cache/film/{id}/
                 ◀── ② SSE 진행 ──                              (썸네일·정보·장면)
미리보기 <img>   ── ③ 원본 프레임 ▶ ffmpeg → 응답으로 바로       (저장 안 함)
```

### 왜 업로드가 없나

브라우저는 사용자가 고른 파일의 실제 경로를 알려주지 않습니다. 경로를 모르면 원본을 그 자리에서 읽을 수 없고 업로드(복사)가 필요해집니다. 그래서 **서버가 `FILM_DIR` 폴더를 직접 읽어 목록을 만들고**, 브라우저는 경로 대신 **소스 ID**로만 파일을 가리킵니다. 서버는 ID를 목록에 있는 파일로만 되돌리므로 폴더 밖 파일에는 접근할 수 없습니다.

### 썸네일 한 장을 빠르게 만드는 법

`ffmpeg -ss {시점} -i {파일} -frames:v 1` — 시점 지정(`-ss`)을 입력 앞에 두면 ffmpeg가 그 시점 직전의 키프레임으로 바로 건너뛴 뒤 필요한 만큼만 디코딩합니다. 그래서 수 GB 영상이어도 한 장마다 영상 전체를 읽지 않습니다. 썸네일은 폭 320px JPEG로 만들고, 임시 파일에 쓴 뒤 이름을 바꿔 반쯤 쓴 파일이 캐시에 남지 않게 합니다.

### 영상을 열면

1. **열기** — 서버가 ffprobe로 길이·해상도·fps·회전을 읽고(`meta.json`에 저장), 보여줄 시점 목록을 정합니다.
   - 균등: 0초부터 N초마다
   - 장면: 영상 전체를 320px로 줄여 한 번 디코딩하며 장면 전환 점수가 0.2를 넘는 시점을 모두 고릅니다 (`scenes.json`에 저장)
2. **생성** — 시점마다 ffmpeg를 실행합니다. 동시에 CPU 코어의 절반까지 돌리고, 캐시에 있는 시점은 건너뜁니다.
3. **전달** — 한 장이 끝날 때마다 SSE(`/api/sources/{id}/events`)로 알립니다. 서버는 보낸 이벤트를 기록해 두어, 늦게 연결하거나 다시 연결한 화면도 처음부터 빠짐없이 받습니다.
4. **화면** — 열기 응답에 이미 캐시에 있는 칸이 담겨 와서 그 칸은 바로 그립니다. 나머지는 SSE로 받는 대로 채우는데, 칸이 수천 개여도 멈추지 않도록 100ms씩 모아 한 번에 반영합니다.

다른 영상을 열면 이전 작업은 취소되고 실행 중인 ffmpeg 프로세스도 종료됩니다. 한 번에 한 영상만 작업합니다.

### 원본 프레임과 저장

썸네일을 고르면 미리보기 `<img>`가 `/api/sources/{id}/frame/{시점}/{원본이름}_03m12s450.png`를 요청합니다. 서버는 썸네일과 같은 방식으로 그 시점에 건너뛰어 **원본 해상도 한 장**을 만들고, 파일로 저장하지 않고 응답으로 바로 흘려보냅니다.

- URL의 마지막 부분이 곧 파일명이라 [다른 이름으로 저장] 창에 그 이름이 뜹니다.
- 같은 URL은 늘 같은 이미지이므로 브라우저가 오래 캐시합니다 (포맷을 바꿨다 돌아와도 다시 만들지 않음).
- ±1프레임은 `1/fps`초만큼 시점을 옮긴 새 URL입니다.

### 화면 상태

화면의 흐름은 XState 상태 머신(`src/machines`)으로 정리되어 있습니다. 화면은 지금 상태를 그리고 이벤트만 보냅니다.

```
opening ──성공──▶ ready ─┬─ stream: streaming ──완료──▶ finished
   │                     ├─ task:   idle ──구간 더 보기/전체 보기──▶ 새 세트로 다시 시작
   │                     └─ 서버가 소스를 잃음 ──▶ reopening (최대 3번) ──▶ ready
   └──실패──▶ failed
```

열린 영상·간격·방식은 URL(`?v=&i=&m=`)에 있어서 새로고침하거나 주소를 공유해도 같은 화면으로 돌아옵니다.

## 캐시

썸네일·영상 정보·장면 분석 결과는 `~/.cache/film/{소스 ID}/`에 저장되고, 다시 열면 바로 보여줍니다.

- 소스 ID는 `상대경로 + 크기 + 수정 시각`으로 만들기 때문에, 파일이 바뀌면 캐시도 새로 만들어집니다.
- 전체 용량이 1GB를 넘으면 오래 열지 않은 영상부터 지웁니다 (시작할 때와 1시간마다).
- 원본 프레임(미리보기)은 저장하지 않고 요청할 때마다 만듭니다.
